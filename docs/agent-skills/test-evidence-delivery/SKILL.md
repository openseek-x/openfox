# 测试取证与报告交付

本技能规定测试智能体如何留下可复核的证据，并把结果交回原任务。对应需求 F01–F07、F10。平台侧上限：每轮产物最多 20 个；HTML 报告在页面内渲染的上限为 10 MB、2 万个节点；录像支持 WebM / MP4，可拖动播放与下载。

## 1. 选择测试载体（F01）

- 先看被测对象：网页用浏览器自动化；桌面端用桌面端的自动化入口；纯接口或后端行为用请求与日志，不要为了截图硬开浏览器。
- 每个用例只选一个主载体，在用例记录里写明载体和选择理由。
- 载体不可用时如实记为「阻塞」，写明原因，不要用模拟结果顶替；确实只能模拟的，标注 SIMULATED。

## 2. 逐步截图并标注（F02、F03）

- 每个关键步骤一张截图：操作前、操作后、出现异常的那一刻。文件名用 `TC-编号-步骤序号-动作.png`。
- 在截图上标注：用红框圈出被验证的元素，用序号写出步骤，失败步骤再加一句预期与实际的对比。标注直接画在图上，不要只写在报告正文里。
- 截图只保留与结论相关的区域，不要整屏堆叠重复画面。

## 3. 录像范围（F04、F05）

- 录像以用例为单位，从该用例的第一个操作开始，到结论出现为止，一个用例一个文件，格式用 WebM 或 MP4，文件名 `TC-编号-简述.webm`。
- 通过的用例只在需要复核动态过程时录像；失败和难复现的用例一定录像，并在报告里写明失败发生在第几秒。
- 不录登录凭据输入、个人信息页和与本任务无关的窗口；录像前先关闭无关通知和标签页。

## 4. 脱敏（F06）

- 先脱敏再截图、再录像，不要事后补救：密码、令牌、Cookie、密钥、手机号、邮箱、身份证号、内部地址都要遮盖或改用测试数据。
- 只使用任务给定的测试账号。日志、请求头和响应里出现的凭据，写入报告前替换为 `***`。
- 拿不准是否敏感的内容，当作敏感内容处理。

## 5. 生成 HTML 报告（F07）

- 报告是一个自包含的 `report.html`：不含脚本，样式内联，截图以 `data:` 位图内嵌，不引用外部地址。
- 结构：结论一句话、用例汇总表（编号、载体、结果、录像文件名）、每个用例的步骤与截图、失败详情、未验证项与剩余风险。
- 控制体积：总大小不超过 10 MB，节点不超过 2 万个。截图过大时先缩放压缩；用例很多时只内嵌失败与关键截图，其余放进证据清单。
- 生成后自查：用浏览器打开一次，确认图片都显示、没有外链、没有脚本。

## 6. 在原任务发布正式报告评论（F07、F10）

1. 用 `openfox_publish_artifact` 逐个发布产物：`report.html`、录像、证据清单，以及少量关键截图。每轮最多 20 个，先保证报告和失败用例的录像。
2. 记下每次发布返回的产物 ID，调用任务评论工具（`task_comment`），正文写结论和报告摘要，`artifact_ids` 填这些 ID（1–20 个，不可重复）。
3. 同一轮只发一条正式报告评论；重复调用会复用同一条评论，只补缺失的附件，不要为了补充再发第二条。
4. 报告附件随评论存在，不能单独删除；需要更正时在评论里说明，并在下一轮重新交付。

## 7. 断点续测（F10）

- 在工作目录维护 `.test-run/progress.json`，每个用例一条：编号、状态（待测 / 通过 / 失败 / 阻塞）、已产出的文件、已发布的产物 ID。
- 每完成一个用例就落盘，不要等全部结束再写。
- 中断后再次被唤醒时，先读这个文件：跳过已完成的用例，沿用已发布的产物 ID，只重测未完成的部分，最后合并生成报告。
- 账本缺失或与现场不一致时，以现场为准重新核对，并在报告中注明。

## 交付前自检

- 每个用例都有结论、载体和证据；失败用例有录像和复现步骤。
- 没有未脱敏内容；报告不含脚本和外链，体积在上限内。
- 产物数量不超过 20，评论只发了一条且附件齐全。
- 没有亲眼观察到的结果，不要写成已通过。
