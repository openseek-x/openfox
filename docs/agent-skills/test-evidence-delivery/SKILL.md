# 测试取证与报告交付

本技能规定测试智能体如何留下可复核的证据，并把结果交回原任务。对应需求 F01–F10。平台侧上限：每轮产物最多 20 个；HTML 报告在页面内渲染的上限为 10 MB、2 万个节点；录像支持 WebM / MP4，可拖动播放与下载。

## 1. 读取派单并选择测试载体（F01、F02）

- 开测前先读派单，逐项记下：测试对象、目标环境、用例及优先级、指定版本或测试机、录像范围（例如「仅录 P0」）。派单没写的项记为「未指定」，不要自己补。
- 进入测试前记录实际环境：被测版本、测试机、浏览器或客户端版本、账号角色，写进报告首屏。
- 先看被测对象再选载体：普通网页默认在隔离的无头浏览器中运行，只有派单明确指定才打开可见窗口；桌面客户端绑定真实测试实例，不用网页替代；浏览器扩展侧栏绑定指定浏览器里实际打开的侧栏；纯接口或后端行为用请求与日志，不要为了截图硬开浏览器。
- 每个用例只选一个主载体，在用例记录里写明载体和选择理由。
- 指定的客户端、版本或入口不可用时，受影响用例标为「环境阻塞」，写明缺什么，不要用模拟结果顶替；确实只能模拟的，标注 SIMULATED。
- 系统弹窗或权限确认需要用户操作时，记录断点（做法见 §7），不要自行绕过。

## 2. 逐步截图并标注（F03、F04）

- 每个编号步骤完成后保存一张完整视口或目标窗口的截图，文件名用 `TC-编号-步骤序号-动作.png`；提交、弹窗、状态切换等关键变化保留前后对照两张。
- 每张图标明用例号、步骤号、操作、观察结果和采集目标（页面、窗口或侧栏）。标注直接画在图上，不要只写在报告正文里。
- 断言位置按实际元素坐标画红框；失败步骤再加一句预期与实际的对比。元素缺失时保留现场截图，在图注里说明缺的是什么，不要凭空画框。
- 保留画面上下文，不要裁成只剩一个控件；报告里用原生 details/summary 包住缩略图，通过 details[open] 的样式放大，同一位置再次点击即可收回。正式交付前在附件预览和离线下载件中分别实点、收回步骤图并核对位置，保留本轮正式 HTML 与录像。
- 带标注的包装截图生成失败时，可改用已脱敏的原图，并在证据清单里记录替代关系。
- 系统级诊断截图（整屏、系统弹窗）另标采集范围，并逐项检查是否带入无关窗口或账号信息。

## 3. 录像范围与采集时间（F05、F06）

- 默认每个已执行用例（含通过用例）各录一段：用例开始时启动采集，从该用例的第一个操作到结论出现为止，一个用例一个文件，格式用 WebM 或 MP4，文件名 `TC-编号-简述.webm`；用例结束时先完成写入，再打开一次确认可播放。
- 仅当派单明确「仅录 P0」时，其他优先级的用例免录，继续按步骤截图，并在证据清单里标「按要求免录」。除此之外不得自行免录。
- 本应录制但没有产出的视频，在证据清单里单独标「缺失」并写原因（例如录制启动失败、文件无法播放、上传失败）。「缺失」与「按要求免录」不要混用，也不要用截图顶替录像。
- 失败和难复现的用例，在报告里写明失败发生在录像第几秒。
- 登录、验证码等敏感阶段暂停采集，恢复后在证据清单和报告里标出跳过区间（例如「跳过：登录，步骤 2–3」）。不录登录凭据输入、个人信息页和与本任务无关的窗口；录像前先关闭无关通知和标签页。
- 允许剪去空闲或按帧合成，但要如实记录：步骤实际耗时、片段播放时长、剪辑方式三项分别写，不要把片长当成步骤耗时（报告写法见 §5）。有响应时间要求的用例，以执行时记录的时间判定，不以录像片长判定。

## 4. 脱敏（F06）

- 先脱敏再截图、再录像，不要事后补救：密码、令牌、Cookie、密钥、手机号、邮箱、身份证号、内部地址都要遮盖或改用测试数据。
- 只使用任务给定的测试账号。日志、请求头和响应里出现的凭据，写入报告前替换为 `***`。
- 拿不准是否敏感的内容，当作敏感内容处理。
- 交付前逐项核查截图、录像、HTML 报告、证据清单和诊断附件的脱敏结果，核查通过再发布；证据清单里每项写明脱敏状态。

## 5. 生成 HTML 报告（F07）

- 每轮生成一个中文、自包含的 `report.html` 和一份证据清单：不含脚本，样式内联，截图以 `data:` 位图内嵌，不引用外部地址；断网打开单个 HTML，正文、按用例顺序的时间线和步骤图仍可阅读。
- 首屏：总体结论、通过 / 失败 / 阻塞 / 未执行等各状态的数量、运行编号、实际环境（见 §1）。
- 用例总表：编号、载体、优先级、结果、录像文件名，每行可跳到该用例的步骤详情。失败、阻塞、低置信度、需人工确认的项排在最前。
- 用例详情按用例号、步骤号列出：操作、预期、实际、步骤实际耗时、图注和可放大的步骤图。用例头部另列录像信息，三项分开写，不要合并：步骤实际耗时、录像片段播放时长、剪辑方式（未剪辑 / 剪去空闲 / 按帧合成，按帧合成时写帧间隔）。例：「实际耗时 42 秒｜片长 11 秒｜按每帧 0.25 秒合成，时长已压缩」。
- 结果分四类，不要混写：业务断言失败、环境阻塞、未执行、证据缺失。
- 录像作为独立文件交付，不内嵌进 HTML；报告和证据清单列出每段录像的文件名和关联用例号，下载后可离线播放。缺陷说明引用「文件名 + 用例号 + 录像起止秒」；关键失败证据单独发布，便于单独下载。
- 证据清单逐项写明：来源、脱敏状态、是否替代（替代了哪一项）、交付状态（已交付 / 待交付 / 按要求免录 / 缺失）。
- 末尾写未验证项与剩余风险。
- 控制体积：总大小不超过 10 MB，节点不超过 2 万个。先缩放压缩截图；仍超限时才保留失败与关键步骤的内嵌图，其余步骤图改为证据清单中的独立文件，并在报告里注明。
- 生成后自查：用浏览器打开一次，确认图片都显示、没有外链、没有脚本；断网再打开一次，确认正文和内嵌图仍完整。

## 6. 在原任务发布正式报告评论（F08、F09）

1. 用 `openfox_publish_artifact` 逐个发布产物，每轮最多 20 个。顺序：`report.html`、证据清单、每个已执行用例的录像，剩余名额给关键失败证据和少量关键截图。报告加录像超过 20 个时，报告、清单和失败用例的录像优先，其余录像在证据清单标「待交付」并写明超出每轮上限，不要标「缺失」或「按要求免录」。
2. 记下每次发布返回的产物 ID。调用任务评论工具（`openfox_task_comment`），正文给出结论和用例统计（通过 / 失败 / 阻塞 / 未执行的数量），`artifact_ids` 填这些 ID（1–20 个，不可重复）。
3. 同一轮只发一条正式报告评论；相同发布重试会复用同一轮记录和同一条评论，只补缺失的附件，不要为了补充再发第二条。
4. 发布后用 `openfox_task_view` 回读，确认附件在原任务里可见，再在当前会话回复一句结论。查看、播放、下载沿用原任务的组织与访问权限，不要另建分享链接。
5. 报告附件随评论存在，不能单独删除；需要更正时在评论里说明，并在下一轮重新交付。

### 部分交付（F09）

- 单件产物上传失败：继续发布其余产物；评论正文列出「已交付」和「待交付」文件，待交付的文件及其脱敏后的证据保留在本地不删，证据清单里把对应项的交付状态标为「待交付」。
- 评论被拒绝：把完整结论和可交付的附件发到当前会话（附件用 `openfox_publish_artifact` 发布，结论写在回复里），并说明评论被拒绝的原因。
- 重试时沿用同一轮的记录（`progress.json` 里已发布的产物 ID），不要重新发布已交付的文件。
- 交付核验通过后（评论回读可见，或当前会话已收到文件）才清理本地交付副本；仍有待交付文件时不清理。

## 7. 人工介入、中断与续测（F02、F10）

- 需要扫码、真人点击或系统许可时，先暂停并向用户说明：测试机、窗口（或侧栏）、用例号、已完成的步骤、恢复点（从哪一步继续）。涉及登录或验证码的，同时按 §3 暂停采集并记录跳过区间。
- 在工作目录维护 `.test-run/progress.json`，每个用例一条：编号、状态（待测 / 通过 / 失败 / 阻塞 / 未执行）、已完成的步骤序号、恢复点、已产出的文件、录像状态（已录 / 按要求免录 / 缺失及原因）、跳过区间、已发布的产物 ID。
- 每完成一个步骤和每完成一个用例都落盘，不要等全部结束再写。
- 中断后再次被唤醒时，先读这个文件：保留已完成的证据，跳过已完成的用例，沿用已发布的产物 ID，从可确认的断点继续，最后合并生成报告。恢复点无法确认时，回到该用例的第一步重测，并在报告里注明。
- 被取消时：保留已完成范围的证据，在报告和证据清单里列出未执行的用例和步骤，状态标「未执行」，仍然发布报告。
- 账本缺失或与现场不一致时，以现场为准重新核对，并在报告中注明。

## 交付前自检

- 每个已执行用例都有结论、载体和证据；每例有一段录像，或在清单里标了「按要求免录」或「缺失」及原因；失败用例有录像起止秒和复现步骤。
- 报告里步骤实际耗时、片段播放时长、剪辑方式分别写明；敏感阶段的跳过区间已标出。
- 截图、录像、报告、证据清单和诊断附件都已核查脱敏；报告不含脚本和外链，体积在上限内。
- 产物数量不超过 20，评论只发了一条且附件齐全，回读已确认；有待交付文件时，评论里已列出已交付和待交付。
- 没有亲眼观察到的结果，不要写成已通过。
