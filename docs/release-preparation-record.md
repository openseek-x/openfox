# 公开发布准备记录

日期：2026-11-09

## 目标与方案

目标是清理当前源码树中对参考产品的名称、域名和内部工作材料的引用，并检查明显的私人基础设施与凭据痕迹。范围包括文档、设计导出、代码注释、测试数据、资源键、导入来源值和迁移文件名。保留现有功能、公开 API 与可执行 SQL 的语义；不执行数据库迁移，也不发布代码。

方案是在本地 `master` 创建任务分支，先盘点，再逐文件改写；移除仅供内部使用的研究、设计和逐阶段记录，修复失效链接，最后检查、提交。参考材料先备份到被忽略的 `work/` 目录。与机械替换相比，逐文件处理可以保留注释含义并识别模糊项。

已考虑将内部材料统一搬到仓库子目录，但该做法仍有误提交风险，因此从版本控制中移除并保留本地备份。发布时应使用无旧历史的新仓库与单个干净的首次提交，而不是推送本清理分支的删除差异。

## 执行步骤

1. 按名称、变体和域名扫描，分类统计并核对当前工作区的既有改动。
2. 从本地 `master` 创建 `codex/open-source-release-cleanup`，再将分支指向包含最新项目代码的本地提交 `516af15`；本地 `master` 停留在较早提交，未修改它。
3. 使用 `git rm` 移除设计导出、截图、产品研究、对照计划、逐阶段记录和只链接这些材料的索引；在文档中修复引用。
4. 清理代码注释、字符串、测试夹具和图标键；检查资源键冲突；将导入来源标识改为 `builtin`。
5. 用文档专用地址替换真实部署地址，移除真实公司邮箱测试值，并扩充本地密钥忽略规则。
6. 核对迁移、格式、链接、敏感信息与项目检查；仅在本地提交。

- 原有 56 个产品前缀图标键已改为 `openfox-*` 并同步调用处；未发现新键冲突。图形作品的来源和许可仍待人工确认，见[图形来源核对清单](asset-provenance-review.md)。

- 对 11 个迁移文件仅改写 SQL 注释；另将编号 105 的迁移文件改为中性名称，文件内容不变。没有修改可执行 SQL、表结构、OpenAPI 请求或响应形状，也没有新增依赖。

本次只改动 `.gitignore`：忽略整个 `.claude/`、根目录 `/test-results/`，以及 `*.key`、`*.p8`、`*.pk8`、`*.p12`、`*.pfx`、`*.jks`、`*.keystore`、`*.kdbx`。这些规则只影响未来的 Git 跟踪选择，不影响运行配置，也不会清除旧提交中的文件。既有 `.env*`、`key/` 和 `work/` 规则保持有效。无新增环境变量或配置键。

没有执行 SQL 语句、数据迁移或回滚语句；没有可执行 SQL 变化。仅注释变化的文件编号按执行顺序为 000021、000024、000033、000034、000043、000044、000048、000058、000059、000062、000087。迁移器将已执行的编号、文件名和 SHA-256 校验和与当前清单逐项比对。因此，已经应用其中任意一个迁移的数据库会因注释变化而出现校验和冲突；已经应用编号 000105 的数据库还会出现文件名冲突。全新数据库按当前文件顺序执行不受此历史冲突影响。不要直接改写生产数据库的迁移历史表；若要继续使用已有数据库，应先设计并审核专门的兼容迁移方案。回退源码可恢复原迁移文件及其字节内容，并重新运行只读迁移检查；没有需要回滚的 SQL 写入。
