# 文件批注与 AI 定向修改

文件默认正常预览。点击右上角“批注”后，选择内容才会弹出意见输入框；开关不改变文件排版。填写意见后点击“添加到聊天”，批注进入左侧待发送区。展开批注可选择“保存为评论”，只保存讨论；也可以直接发送聊天消息，请 AI 按要求处理。AI 修改先生成候选，原件保持不变。从会话顶部“更多操作 → 修改提案”打开审阅标签；明确接受后，“当前”标签才跟随新版本，固定版本标签保留原文件。输入框上方不常驻评论/提案管理卡片，右侧也没有评论管理或版本历史侧栏。

这一交互参考 [Codex 行内评论与后续消息](https://learn.chatgpt.com/docs/code-review?surface=app#inline-comments-for-feedback)。文件批注是当前聊天的上下文，仍使用该聊天的历史、工作目录、工具与执行权限。只读或计划模式不能通过批注工具写入文件；提问也不应被当成修改指令。


## 独立评论与 AI 请求

- 在左侧待发送批注中展开来源，点击“保存为评论”。成功后可从会话顶部“更多操作 → 已保存的评论”查看；失败保留草稿。管理窗口按需打开，右侧继续完整预览，不增加评论或历史侧栏。
- 已保存评论支持回复、编辑自己的文字、手动解决与重开。读取需要会话及来源权限；写入还要求可评论权限。每次更新检查版本，别人已更新时保留输入并提示重新确认。
- 点击某条评论的“交给 Agent”只复制该条评论及其来源锚点、评论版本到待发送草稿。仍需点击聊天发送；复制之后继续编辑原评论不会改变该草稿或已发送请求。发送、运行完成或取消均不自动解决评论。
- 来源版本和锚点不随讨论编辑变化。文件更新后仍能读取已有讨论，但旧来源不能绕过修改前的版本检查；可显式定位到当前版本，或重新选择内容。普通讨论可重叠，只有实际同时替换重叠区域才拒绝。
- 每会话最多 200 个线程、每线程 50 条评论及 120 KiB、单条文字 8 KiB；列表每页 20 条。展开列表后每 15 秒刷新，未提供多人实时协同。保存的网页截图独立保留；交给 Agent 时复制为新消息附件，原图不会被消息占用或被当作待上传附件删除。
- 评论与回复保存在服务端；未发送草稿及结果不确定的更新操作保存在本机工作区，刷新后可重试原操作。修改提案另行审阅，不会因保存评论、运行完成或关闭标签而自动接受。


## 支持范围

| 文件                       | 如何选择                                                  | AI 修改范围                                          |
| -------------------------- | --------------------------------------------------------- | ---------------------------------------------------- |
| Markdown、UTF-8 文本与代码 | 在排版预览或源码中拖选文字                                | 所选源码文字                                         |
| CSV                        | 点击单元格                                                | 单元格内容，保留其他字段                             |
| HTML                       | 在静态预览中拖选文字，或选择源码                          | 所选文字对应的原始源码；不运行文件脚本或加载外部资源 |
| DOCX                       | 在原页面选择正文/表格文字，或框选区域                    | 已映射文字可精确替换；布局等修改通过独立文件副本交付 |
| XLSX                       | 选择工作表、单元格/矩形范围，或图片/图表对象            | 常量可精确替换；公式、范围、图表等通过独立副本交付 |
| PPTX                       | 在原幻灯片选择文字、形状/图表或区域                    | 文字可精确替换；图表、布局等通过独立文件副本交付 |
| PDF | 选择文字（支持多行），或切换为区域/整页 | 文字、页码、四边形与意见作为上下文；不直接改写 PDF |
| 图片 | 框选区域或选择整页，按 EXIF 方向显示 | 区域与意见作为上下文；不直接改图 |
| 资料库原生 Markdown | 聊天中的文档卡片，或新标签搜索本空间文档；画布中编辑，开启批注后选择文字 | 批注先保存正文，绑定精确版本；AI 生成候选，接受后保存到资料库 |

Office 原版式预览保留页面、幻灯片和工作表，支持中文、图片、图表、合并单元格与数字格式。Word/PPT 文字定位到原文件片段；Excel 常量定位到原工作表和单元格，范围批注记录原表部件、A1 地址及内容快照。图形区域是修改意见的位置提示，不能当作精确源元素 ID。无法映射的内容可框选并描述要求；Agent 不能确定如何修改时应说明限制。

精确修改只接受已校验的文字/常量，保留未选内容；数字仍须是数字，布尔值使用 `0` 或 `1`，文本不会自动变成公式。公式及复杂修改由 Agent 导出原文件、编辑独立副本，再交付新文件。服务端检查格式、源摘要、选区和权限，但不能证明整文件修改的每个语义都只在选区内；用户应核对新预览。预览引擎只支持部分 Excel 公式，最终计算结果请用 Excel 核验。

Office 原生预览超限或不支持时，可使用已有 PDF 转换服务；转换不可用时明确显示失败并保留下载，不退回文字大纲冒充原版式。宏、加密文件、任意 OLE 和受保护内容仍受原有格式/编辑限制，不能保证与 Microsoft Office 对所有特性逐像素一致。

### Office 特性与往返边界

| 特性 | 当前支持 | 修改、导出与限制 |
| --- | --- | --- |
| Word 正文、表格、分页、中文与图片 | 原页面预览；映射成功的普通文本片段可批注 | 精确替换同一文本片段，保留该片段样式及其它 ZIP 部件；跨样式/域/复杂结构保守只读，不能据此承诺所有 Word 文件版式完全相同 |
| PPT 文字、配色、布局、形状与图表 | 原幻灯片预览；文字源映射与对象/区域反馈 | 文字可精确替换；主题、母版、图片、关系等未编辑部件原样保留。图表、动画、排版修改需交付独立副本并重新审阅；不提供演示播放或动画编辑 |
| Excel 常量、格式、合并、冻结区、隐藏行列、图片与图表 | 工作表预览；单元格/范围/对象批注 | 已有文本、有限数值和布尔常量可精确修改；文本不会自动成为公式，合并区仅使用原单元格身份。公式、复杂富文本、受保护内容不走常量替换 |
| Excel 公式与图表缓存 | 预览副本使用有限公式/缓存处理，源文件和预览副本分离 | 精确修改常量后清理原包公式缓存并设置打开时重算；不保证复杂公式、外部数据、图表或动态计算已更新。下载的是候选 OOXML，最终结果需用 Excel/LibreOffice 重算核验；这里不是完整重算引擎 |
| 不支持或渲染失败 | 尝试已配置的 PDF 转换；无转换能力则显示失败与下载入口 | PDF 降级只能区域反馈，不能冒充精确 Office 源定位；加密、宏、签名、任意 OLE 和受保护内容不承诺可编辑或无损 |

本轮往返样本为 `complex.docx`、`complex.xlsx`、`styled.pptx`：分别替换普通标题、B3 数值、幻灯片标题；重读 OOXML 确认结果，检查未编辑包部件字节不变，再以构建产物与部署 CSP 渲染、比较批注开关前后画布，并核对实际下载 SHA256。样本覆盖不等于任意 Office 文件无损；复杂结构应重新检查候选预览和原生应用的计算/版式。完整 Office 编辑 SDK 尚未接入。

### 原生文档画布

聊天中的原生文档卡片可直接打开右侧画布；“+” 新标签页也可搜索当前空间文档。复用资料库 Markdown 编辑器、原有文档权限与历史修订，支持直接编辑和自动保存。历史通过工具栏弹窗按需查看，不占据固定右侧区域。产物文件版本仍走不可变预览与提案流程，不会把上传的任意代码/文本文件自动变成可编辑资料库文档。

批注默认关闭。开启后可用鼠标或 Shift+方向键选择文字，浮层填写意见；提交时先保存当前正文，再按 UTF-8 字节与 SHA256 绑定已保存版本。前方插入文字由编辑器事务移动选区，选中文字改变、删除或不能精确序列化时要求重新选择。收起输入保留意见草稿，没有语音入口。

正文草稿按账号/组织保存到本机。远端保存失败或版本冲突时保留本地内容与原基线；先比较远端正文，只有显式合并才基于新版本保存。还有本地修改时，先打开文档并保存，再接受 AI 提案；服务端仍核验基线，旧候选不会覆盖后来的正文。本机存储失败时保持页面打开并处理工作区保存错误，不将内存内容视为已经持久化。

PDF 文字层沿用原页面绘制，批注开关不改变排版；多行选区保存未旋转 PDF 用户坐标的四边形，缩放和旋转后重新投影。原文件已有批注以外观及只读文字呈现，不启用其中的脚本、链接、附件或表单。扫描件、无文字层或文字层解析失败时可以选择区域；不提供 OCR。图片区域使用浏览器按 EXIF 方向显示后的归一化坐标。

图片/PDF 文件工具提供元数据、页码/坐标、评论及 PDF 客户端引用文字；引用文字不等于服务端核实的原文，不能用于精确修改。工具不提供区域截图，不能把“能框选”理解为模型已经看到了区域图像。

## 跨版本定位与网页重新绑定

- 在“更多操作 → 已保存的评论”中点击“定位到当前版本”。服务端读取原始版本及当前版本，保存独立的定位结果（AnchorResolution）；原评论、原引用和原位置保持不变，定位本身不启动 Agent。
- 结果分为精确、近似、存在歧义和无法定位。只有精确结果可以复制为当前来源的 AI 请求；仍须点击聊天发送，并经过当前权限、摘要、引用与修改范围校验。后三种结果需要重新选择，不静默猜测。
- 文本/CSV 核对原引用，重复文字使用附近上下文消歧；Office 重新解析原文件，按完整内容单元核对文字/单元格，Excel 范围核对原工作表及区域内容，PPT 保留部件/形状映射。位置编号本身不被视为跨版本身份。内容变化或重复时保守返回近似、歧义或失联。
- PDF/图片仅在文件字节完全相同时保留精确位置；内容变更后不推测旧坐标对应的新区域。PDF 文字的“精确位置”也仅表示同一文件内的位置可复用，不支持 PDF 精确内容编辑。
- 网页重新加载或子 frame 导航后，旧 live 引用失效。点击“重新选择网页元素”，在当前网页选中元素并确认后保存独立绑定结果；不会自动恢复选择模式、旧控制权限或自动发送消息。旧截图与锚点继续保留。
- 每个评论线程最多保存 100 个定位结果；相同请求 ID 的重试返回原结果。浏览器本机记住当前选用结果和未确认请求，清除本机工作区数据后可重新定位。资料库正文可重新计算锚点并交给 Agent；侧栏的可编辑文档画布属于后续阶段。

## 操作步骤

1. 在聊天中打开文件，点击右上角“批注”，再选择要修改的内容。
2. 在选区旁弹出的输入框填写修改要求，点击“添加到聊天”，或按 ⌘/Ctrl+Enter；Esc 或点击外部取消。表格/Office 点击内容单元，PDF 选择文字或区域，图片框选区域，也使用相同浮层。可以继续添加多条。
3. 在聊天输入框上方展开文件批注卡片核对选区和意见，可以删除单条意见或整个文件的批注。填写额外要求后点击普通“发送”；只有批注时会使用默认修改请求。
4. AI 在当前聊天内读取并生成候选。打开会话顶部“更多操作 → 修改提案”，点击文件名，在右侧切换“原件 / 候选”；文本还可查看“差异”，Office 可按原版式预览并分别下载。
5. 点击“接受修改”才更新正式文件或原生文档；“拒绝”保留原件。服务端重新检查当前权限和基线；原件已修改则提示冲突，不覆盖、不自动合并。确认结果不明时保留原操作，使用“重试确认”；刷新后读取已接受/已拒绝结果。
6. 历史文件的“更多预览操作”提供“将此版本作为恢复候选”，确认接受后追加新版本；不会把当前版本号倒退。原生资料库已有历史恢复继续使用版本检查并追加修订。

开启批注后，Office 文字/单元格与 HTML 段落可通过 Tab 聚焦后按 Enter 选择；Excel 支持方向键移动、Shift 扩选。Markdown 使用解析器的原始位置定位，重复文字不会误定位到第一处；HTML 会把实体、换行与嵌套文字映射回原文件。文本类文件无法可靠映射时可切换到“源码”选择。

会话文件是上传的产物快照，文件名不是电脑上的可靠源路径。接受批注修改候选后，会在同一逻辑内容下发布新的不可变版本；不会据此猜测路径覆盖电脑项目文件。普通上传建立独立内容，同名或同摘要不会自动合并版本链。原始上传对象由既有产物保留策略管理。

产物列表默认打开“当前”标签；聊天中的具体文件链接打开固定版本。通过“更多预览操作”可将同一内容的当前版和固定版同时打开，各自保存预览/源码、页码、缩放等视图状态。历史版本只读，不将旧选区用于当前版修改。文件的逻辑身份是 `content_id`，不可变版本身份是 artifact ID，序号是 `content_revision`；原有 `version` 仍是状态、置顶等元数据的并发版本。资料库继续使用 node/version/doc_revisions，网页仍使用 capture 和 document generation，不混成文件版本。

## 限制与失败处理

- 目前需要单个 Codex Agent 的聊天、在线且支持动态文件工具的电脑，以及有效执行权限。
- 一条消息最多附带 10 个文件、合计 20 条批注；单个选区/评论最多 8 KiB，结构化上下文最多 256 KiB。消息正文与可读批注合计还受普通消息的 64 KiB 限制。
- 尚未发送的批注按账号/组织保存到本机，切换聊天或刷新后恢复；保存失败会显示提示。清理站点数据或退出登录会清除对应本地记录。发送后意见及选区随消息存储，发送失败保留草稿。
- 发送后的批注不会随新草稿改变；AI 执行时新添加的批注留给下一条消息。
- 文件改变后可以显式重新定位或重新选择；服务端检查当前摘要、原文和定位，拒绝过期或重叠修改。精确定位结果也不能绕过之后发生的版本变化。
- 文本 ≤5 MiB，Office/图片/PDF ≤10 MiB。HTML 静态预览另限 512 KiB、10,000 节点及 128 层；超限文本可转源码。Office 还限制解压量与内容单元数量。
- 一次运行可以为多个文件生成候选，每份单独接受或拒绝；多个文件不构成整体应用事务。生成候选失败不会让其他待审阅候选自动生效。
- 同一批注上下文允许不同的完整候选；相同请求重试复用候选。相同基线只能接受一份，其他候选再接受会提示冲突。混合文字与复杂修改应在一个副本中一并完成。每个 Run 的正式文件与候选合计最多 10 份，并共用组织文件字节预算；拒绝候选仍保留审阅记录和内容。
- 没有新增文件历史或撤销面板。不要把模型的文字回复等同于实际文件已修改；以更新后的预览/下载内容为准。
