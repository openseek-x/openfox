**优先把有任务的列带入看板首屏。** 在 960 × 640 窗口、默认导航和标准密度下，测试空间有 7 条任务，进入时却读不到任何一张卡片的标题。其次，窄收件箱应优先给任务名分配宽度，浅色主题的默认待开始圆环应更容易辨认。对照 HiFox，两者的全局导航、全页详情和对话阅读顺序已经接近。

## 复核方式

- **环境与样本**：同一份本地 master、独立 PostgreSQL、真实 Go API 与 Chrome，简体中文、标准密度、默认侧栏。通过仓库的开发服务与测试种子登录两个示例账号 `alice@example.test`、`carol@example.test`。7 条示例任务在 3 个状态中分布为 3、2、2，前两个状态为空。通过页面在三项任务上分别提及另一账号，得到 3 组实际通知。Agent 对话文案为 SIMULATED 夹具。启动方法见 [Web 开发说明](../../apps/web/README.md)。
- **复核动作**：打开空间任务，分别进入 `?view=board|list|table` 所对应的布局。先在 1440 × 900 观察，再在 960 × 640 初次进入看板并用「定位列」跳到首个非空列。用同一任务比较抽屉和全页。切到接收方的收件箱，量取标题元素的 `clientWidth/scrollWidth`，并记录往返分区前后的 `aria-checked`。在设置切换浅、深主题，读取状态图标的 computed stroke 与最近不透明背景，通过 sRGB 相对亮度计算比值。
- **保护既有行为**：`d420ae3` 明确保留空状态拖放目标，[既有开发记录](2026-11-24-workspace-reading-chat.md) 也记载了键盘定位。集成分支另有 `629b3fe` 的对话输入区样式优化。实际对照覆盖全页详情与历史会话，建议不重复该改动。
- **证据边界**：报告中的截图和数值是当前基线；建议后的结果是验收目标。未做用户计时、原生手机、屏幕阅读器或 HiFox 登录态的同数据实验。生产任务量、更多主题和实际团队重要/其他混合队列的收益仍待实施时复核。

## 四项建议的实现与实测

用户确认将上述四项纳入本任务。实现沿用既有 API 和数据模型。下表使用评估时相同的 7 条任务与 3 组真实提及通知，列出实现后的浏览器结果。

| 用户路径 | 实现后结果 |
| --- | --- |
| 首次打开 960 × 640 状态看板 | 首个有任务的列自动进入可视区。首标题左界从 x=994 移到 x=394，看板右界为 x=952。仍有 8 个状态可定位和拖放。 |
| 宽屏、手动定位与历史返回 | 1440 × 900 首次进入的横移量为 0。手动定位「待规划」后焦点位于列头；将看板滚到 222 px、打开收件箱并返回，恢复至 222 px。 |
| 阅读收件箱 | 标题、摘要在窄列表中分两行，时间按内容取宽。三条样例标题都能读全，DES-1 获得所需的 168 px。宽列表仍为单行，时间和计数区为 128 px。 |
| 往返分区 | 选择「重要 3」、打开「稍后」再返回，选中项仍为「重要 3」。稍后和已清理使用各自的查询范围。 |
| 辨认待开始状态 | 默认圆环采用主题中的次要文字色。按实际描边与表面色计算，浅色为 4.83∶1、深色为 5.81∶1；显式配置的其他颜色原样显示。 |

实现仅在状态看板首个非空列的标题加载后决定是否滚动。指针操作、滚轮和手动聚焦均优先于自动定位。历史位置保存在当前页面会话内，最多记住 32 个导航条目。收件箱用列表容器的 48 rem 断点决定单行或双行，侧栏调整宽度时也会生效。

验证结果：首次默认并发全量运行有 10 项失败。限制为三个工作进程后，`VITEST_MAX_WORKERS=3 pnpm test` 全量通过（Vitest 2321 项、桌面端 129 项）。`pnpm lint`、`pnpm build` 通过，与本次修改相关的 Playwright 用例 15 项通过。

## 追加：全局背景与面板色调统一

提测前复核时发现，全局背景（`surface-app`）和上方面板（`surface-card`、侧栏）色调不一致，看起来分成了两块。魔法蓝和经典深色的全局背景是中性的近黑色，面板却是带色相的；魔法蓝缩略图甚至外层比内层更亮。这次只改设计令牌和设置页缩略图色，不动布局。

| 主题 | 变量 | 原值 → 新值 | 全局背景与面板对比（新） |
| --- | --- | --- | --- |
| 浅色 | `--color-surface-app` | `#efeff4` → `#f0f0f2`（去掉偏紫，改为中性灰） | 1.14∶1 |
| 深色 | `--color-surface-app` | `#18181b` → `#1f1f23`（与侧栏同色，比面板 `#27272a` 暗一档） | 1.10∶1 |
| 深色 | `--color-surface-canvas` | `#09090b` → `#232326`（画布令牌） | 画布令牌与面板 1.05∶1 |
| 魔法蓝 | `--color-surface-app` | `oklch(0.12 0.005 285.823)` → `#1a1d36`（与面板 `#222542` 同色相） | 1.11∶1 |
| 经典深色 | `--color-surface-app` | `oklch(0.12 0.005 285.823)` → `#101010`（与面板 `#161616` 同为中性） | 1.05∶1 |

`packages/app/src/me/PreferencesPage.tsx` 中 `PREVIEW` 缩略图色板按上表同步，缩略图外层重新比内层暗。

验证：同一份独立 PostgreSQL、Go API 和网页开发服务（4187），用 Chrome 依次切换四个主题，截取偏好设置、任务表格和看板，共 12 张截图。各页 `body`、外壳和 `main[data-org-main]` 的计算背景色都与上表一致。`pnpm lint`、`pnpm build` 通过；`VITEST_MAX_WORKERS=3 pnpm test` 全量 231 个文件、2321 项通过。

配置与迁移：只改 CSS 设计令牌，不涉及配置文件、SQL 或数据迁移。回滚方式是还原上表中的五个令牌值和缩略图色板。

剩余风险：经典深色的层次对比只有 1.05∶1，主要靠面板圆角和描边区分；深色侧栏与全局背景现在是同一种颜色，左侧导航面板的边界靠其外层面板来表达。截图里两者都能分清，但尚未在低亮度、低色准的显示器上复核。
