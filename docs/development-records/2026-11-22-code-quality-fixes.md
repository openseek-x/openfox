## 数据库、配置与回滚

先执行 [000171](../../db/migrations/000171_draft_notifications_and_export_cleanup.sql)，再执行 [000172](../../db/migrations/000172_result_confirmed_exit_evidence.sql)，之后启动更新后的中心与设备程序。两个文件是本次全部 PostgreSQL 迁移语句。均以迁移角色执行并在末尾恢复角色。

1. 000171 依次替换 `notify_task_draft(uuid)`、建立部分索引 `export_jobs_cleanup_pending`、替换 `list_export_organizations(uuid, integer)`。索引覆盖有残留文件键的过期记录。函数保留原权限。建索引和 000172 的约束校验均需持锁，已在独立测试库从空库执行。
2. 000172 在一条 `ALTER TABLE` 中替换 `run_reconciliation_evidence_exit_shape` 约束，允许 `RESULT_CONFIRMED` 携带已退出标志。集成测试首次打开真实成功路径时暴露了数据库与 Go 校验的差异。迁移不改写既有业务数据。
3. 应用运行时的写入包括条件删除附件、按需重排任务顺序、条件推进触发器、更新命令期限和分拣活动、标记过期并确认文件清理，以及设备本地的终态诊断和补传队列确认。SQLite 表结构保持现状。
4. 本次没有生产配置键、凭据变更或外部部署。测试总入口只为自身建立的 PostgreSQL 集群传入管理连接，并为 Bugly、CodeCommit 分配独立数据库。需要浏览器专用夹具或真实模型的跳过项按具名测试和对应环境开关识别。GitHub 锁顺序测试直接读取实时锁等待并确认已锁定目标行。
5. 本地代码可通过切回原分支恢复，须先保留工作区改动。数据库优先保留向后兼容的新增约束范围。若必须回退 000171，使用后续迁移恢复 [000170](../../db/migrations/000170_standalone_task_drafts.sql) 和 [000054](../../db/migrations/000054_task_exports.sql) 中相应函数定义，并执行 `DROP INDEX openfox.export_jobs_cleanup_pending`。回退 000172 前先检查是否已有 `kind='RESULT_CONFIRMED' AND process_exited` 的证据，有记录时保留宽约束或恢复完整测试快照。收紧定义见 [000014](../../db/migrations/000014_wp13_reconciliation.sql)。回退应用时应保留已经按现有顺序重分配的有效排序键。

## 桌面端回归补验

在临时用户目录中启动 Electron，用两个本地 HTTP 服务分别模拟两个服务地址。修复前的主进程在离线页补填地址并重试后可以加载网页，但从真实渲染进程调用账号列表得到 `account registry unavailable`。

修复后的同一路径可以列出并新增账号。切到新账号后原账号的 Cookie 不可见，切回后能再次读到它。关闭第一个 HTTP 服务、重新加载进入离线页，再配置第二个服务地址并点击重试，新窗口读到了第二个地址已保存的账号，Chromium 实际使用的会话分区与该账号一致。此用例连续运行三次通过。桌面 Node 套件复跑 122 项全部通过。

[桌面包配置](../../apps/desktop/package.json) 增加 `test:accounts:electron` 测试入口，可执行 `pnpm --filter @openfox/desktop test:accounts:electron`。此次补验只增加测试及测试命令，不涉及数据库、生产配置或安装包发布。
