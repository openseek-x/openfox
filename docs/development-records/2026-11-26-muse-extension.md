# Chrome 侧边栏接入 OpenFox（OPE-18）

在 Chrome 的原生侧边栏中，用户可以用现有 OpenFox 账号与空间里的 Agent 对话。扩展复用了工作台的 API 客户端、组件和权限判断。安装与使用见[扩展说明](../../apps/extension/README.md)。

## 初版实现记录（登录方式已由下文修订）

- 以 Muse 的侧边栏对话和选区引用为范围。在网页设置中生成个人访问令牌，扩展向用户填写的服务器申请主机权限。令牌只存于当前浏览器，断开连接会同步更新其他面板。
- 工具栏点击或快捷键触发 `chrome.action.onClicked`，在同一用户手势中调用 `chrome.sidePanel.open`。实测仅设置 `openPanelOnActionClick` 能打开面板，但在测试用的跨站网页上得不到读取选区所需的临时授权。
- 对话保存在现有服务端。按组织读取、按空间显示历史会话，支持翻页与阅读更早消息。发送时锁定目标，失败重试复用消息 ID、正文与页面快照。回复按游标增量读取，面板隐藏时暂停。
- 只有本次发送勾选引用时，才读取当前主文档的标题、地址与选区。地址去掉凭据、查询参数与片段。扩展对页面使用的能力限于读取这些信息。当前集成不提供浏览器代操作、个人设备 MCP 或 Meta 连接器。

## 初版验证

| 验证 | 观察结果 |
| --- | --- |
| 原生侧边栏 | Chrome for Testing 156 加载构建目录。工具栏打开原生侧栏，能连接隔离的 OpenFox 服务和 PostgreSQL 17。测试配置预先允许本机 API 主机。 |
| 对话与引用 | 私有会话创建和两次消息提交均返回 201。勾选时数据库中有标题、裁剪后的 URL 和选区，下一条未勾选的消息只有正文。重新加载后可打开历史会话。 |
| 权限及异常 | 无效及吊销的令牌返回 401。服务端关闭会话后，继续发送返回 409，面板禁用输入。拒绝服务器主机权限时不发请求，已由组件测试覆盖。 |
| 回复显示 | 真实消息 API 将测试夹具写入的 Agent 回复送至面板。回复内容为 SIMULATED，模型运行仍待测试。 |
| 扩展专项 | 46 个测试通过，覆盖连接、凭据处理、重复提交、选区、游标、空间隔离、已关闭会话和账号变更。类型检查与扩展构建通过。 |
| 仓库回归 | Web 构建、前端 lint、桌面测试及 175 项迁移清单校验通过。全库检查另有导航记忆、Web 布局和 Go 失败，其中导航记忆、三项 Web 布局、stage8d 编译和 CLI 工具探测超时均在本地 master 基线复现。 |

声明的最低版本为 Chrome 116，本次浏览器实测版本为 156。首次点击原生权限确认按钮、最低版本以及连接真实模型并执行一次运行，留给提测复核。

## 侧栏 UI 修订

连接页将工作台地址、令牌获取说明与权限用途放在同一表单。对话页把账号、历史会话和新建操作集中到顶栏，当前空间和 Agent 并排显示。引自网页的消息默认显示标题与站点，可展开选区和来源地址；普通消息仍按原文显示。引用开关与发送按钮位于输入框内。

在 Chrome 156 原生侧栏用同一段对话对照改版前后效果。320px 和 390px 宽度下均无横向溢出，输入区完整可见。实际完成按键发送、展开引用、历史重开、关闭会话后的写入拦截及断连。扩展专项 53/53、全仓 lint、扩展和 Web 构建通过。Agent 回复内容来自隔离数据库夹具。

## 网页登录自动连接当前 Chrome

用户明确要求登录后自动连接。扩展复用工作台现有网页会话，未登录仅显示「登录 OpenFox」，进入工作台原有邮箱验证码页面；已登录直接显示对话。注销或切换账号会重置侧栏会话、草稿和待重试消息。安装包按部署变量 OPENFOX_PUBLIC_URL 生成限定站点权限。用户无需输入地址、创建个人令牌或手动配对。网页引用仍由用户逐条选择。

核对的是 Meta 帮助中心的 Chrome 扩展使用流程。其官方资料说明安装后登录 Muse 账号，未公开认证实现。[Meta 官方说明](https://www.meta.com/en-gb/help/superintelligence/2124746764949121/)

在 Chrome 156 原生侧栏和隔离的 OpenFox 服务上，用户在工作台页面完成邮箱验证码登录后，侧栏直接显示本人、空间与 Agent；第二个 Chrome 配置仍停留在登录页。消息经已认证用户会话落库，历史重开与 409 禁发通过。工作台注销后输入区消失，换号后未携带旧对话或草稿。扩展专项 48 项全过。浏览器测试账号只存在于隔离环境，回复文本由测试夹具给出。
