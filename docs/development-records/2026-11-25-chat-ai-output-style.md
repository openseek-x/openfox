# 对话区 AI 输出样式精简（OPE-12）

2026-11-25，从本地 master 的 1f4d3db 切出 `feat/ope-12-chat-ai-output-style`，在独立工作树 `/Users/puhuajie/OpenFox-worktrees/OPE-12-dev` 中开发。

## 任务与范围

对话区 AI 回复观感偏重，希望更简洁易读。先在真实页面渲染一条典型回复，内容含标题、列表、嵌套列表、表格、引用、代码块、分隔线和工具过程，再定位问题。实测发现五处问题：

1. 过程说明（如“我先查看请求拦截器……”）与最终结论同色同字重，读者分不清哪句是过程、哪句是结论。
2. 三列短表格被拉满到 766 px，列间大片空白，行悬停底色在阅读场景里是噪音。
3. 引用块同时有底色、3 px 左边框和圆角，看起来像一张卡片。
4. 列表每项 28 px（24 px 行高加 4 px 间距），嵌套列表显得松散。
5. 结尾分隔线偏重。

提测反馈（“各种命令展开的呢”）后补充第二轮：把命令、MCP 工具、编辑、写入、搜索、网页、任务计划 9 类步骤全部展开后渲染，又发现两处问题：

6. 命令展开后同一条命令出现三次（标题、`$ 命令` 灰块、输出灰块），无输出时“命令没有输出。”也独占一块灰底，工作目录另占一行。
7. MCP 工具单独带外框卡片，表头样式和展开缩进都与同组的命令、读取等步骤不一致。

非目标：设计令牌、代码块（复制、30 行折叠）、消息操作栏（d420ae3 刚调整）、自写的 `Markdown.tsx`（评论、私聊、文件预览使用）、依赖、接口与数据。

初稿还怀疑工具调用行、标题层级和 Git 统计卡有问题。实测工具过程结束后已收成“已完成 x 秒”“已执行 n 项操作”两行，标题间距合理，统计卡只在有 Git 摘要时出现，因此这三项不在本次范围内。

## 实现

只调整元素类名，没有引入 `@tailwindcss/typography`，也没有新增令牌。

- `ChatMarkdown.tsx`
  - 引用块去掉底色和圆角，改为 2 px 左边线加次要文字色。
  - 表格外框改为 `w-fit max-w-full overflow-x-auto`，表格去掉 `w-full` 与行悬停底色，表头底色保留。
  - 列表项间距从 4 px 改为 2 px，嵌套列表上边距同步收紧。
  - 分隔线改用弱分隔色 `line-soft`。
- `steps/rows.tsx`：过程说明的处理在提测时由任务创建人改选为 Q2=C，即默认折叠。`TurnActivityList` 在回合结束且未展开时，把 `agent_text` 和成功的准备、思考一起收进“已完成 x 秒”。展开后，说明按原顺序显示；运行中照常实时显示。被隐藏的说明不再打断相邻工具的分组，所以收起时会合成一行“已执行 n 项操作”。前两轮实现的弱化文字色（Q2=A，`text-fg-muted` 容器）已撤回，`AgentTextRow` 恢复原样。
- `steps/rows.tsx`（第二轮）
  - `ExecRow`：命令行与输出合成一个终端块，工作目录作为命令前缀放在同一行，输出和无输出说明用分隔线接在下面。删除不再使用的 `CodeBlock`。`ExecOutput` 增加可覆盖的 `className`，工具调用沿用原来的灰底。
  - 深色主题与两套深色配色里 `line-default`、`line-soft` 都与 `surface-muted` 同色，所以终端块内的分隔线改用 `line-strong`。
  - `ToolCallRow`：去掉外框卡片和展开区的上边框，展开内容与其他步骤一样缩进 32 px，参数和结果块内边距与命令输出统一为 `px-3 py-2`。
- 测试：
  - `ChatMarkdown.test.tsx` 新增引用、短表与宽表、分隔线的用例。
  - `steps.test.tsx` 新增以下用例：
    - 过程说明在结束后默认收起、展开后按原顺序出现、空说明不渲染。
    - 运行中的过程说明实时显示。
    - 命令与输出同属一个终端块。
    - 工具调用无外框。
  - 原用例“仅分组相邻工具，完成后保留说明……”按 Q2=C 改为：收起时说明隐藏、4 项工具合成一组；展开后说明回到原位，工具重新分成两组。

## 问题与调整

- 截图脚本最初用 `__dirname`，在 ESM 下不存在，改为固定证据目录。
- 宽表校验第一次取到用户气泡（第一个 `message-content`），改为取包含表格的回复。
- 新增用例原本用 `not.toContain("hover")`，但表头底色令牌名 `bg-surface-hover` 里也含该子串，误报失败。改为只排除 `tr:hover`。
- 过程说明颜色从 `fg-secondary` 改为 `fg-muted`，原因见“实现”一节。
- 第一轮只看了工具过程收起后的样子，没有逐个展开，漏掉了命令与工具展开后的问题。提测反馈后补做全部展开的截图。
- 终端块分隔线最初用 `line-soft`，深色截图中看不见，查令牌后改为 `line-strong`。

## 影响面

`ChatMarkdown` 还用于产物 Markdown 预览与批注模式，那里的表格、引用和分隔线会同步变化，保持一致。`TurnActivityList`、`ExecRow`、`ToolCallRow` 也用于 Agent 设置里的运行记录弹窗，那里结束后的过程说明同样默认收起，命令块和工具行也同样变化。

## 风险与回退

- 过程说明默认收起后，若某次运行的结论只写在过程说明里，没有作为最终回复上报，结束后需要展开过程才能看到。按适配器契约，最终回复走 output 或消息正文，过程说明只承载 commentary。
- 剩余风险：Electron 原生窗口和真实 Agent 长回复未实测。中文长表头在窄面板中依赖 `whitespace-nowrap` 加横向滚动，行为与改动前相同。
- 后续：Markdown 排版令牌化，以及 `Markdown.tsx` 与 `ChatMarkdown` 的统一，可作为架构后续单独评估。
- 回退：单个提交，`git revert` 即可，无数据影响。
