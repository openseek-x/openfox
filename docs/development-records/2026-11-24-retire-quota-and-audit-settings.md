# 移除组织设置中的资源配额和审计日志

## 范围与实现

最初的修改只隐藏了导航。组织所有者仍能用旧地址打开页面，对话队列满时也会出现指向配额页的链接。本次沿这两个入口追踪调用，删除专用实现，并保留任务派发、电脑策略同步和业务审计所需的能力。

1. 删除两个设置页、路由、导航项、专用权限组件、查询、客户端 SDK 方法和中英文文案。旧地址由既有的设置路由兜底处理。
2. 删除组织审计列表的 HTTP 处理器、查询构造、游标、筛选器和读模型，并同步移除 OpenAPI 操作与生成类型。成员变更、运行核对等操作仍在各自的事务中记录审计事件。
3. 对话组件直接查询队列状态。队列满时会告知用户消息已保存，以及何时开始处理。服务端只返回组织 ID、排队数、是否已满，所有者和管理员还可看到上限。组织运行策略读写和设备策略确认仍服务于实际运行时。
4. 移除已下线页面和列表查询的测试，把共享电脑确认、核对状态和队列提示的有效测试放回各自模块。补充旧 URL、旧 API 和按角色返回字段的回归断言。

## SQL、配置与发布

删除审计列表使用的只读分页 SQL。队列提示沿用既有的组织策略读取，另执行以下一条查询，省去槽位和预留量查询。

```sql
SELECT count(*) FROM openfox.runs
WHERE organization_id = openfox_private.current_organization_id() AND state = 'QUEUED';
```

本次没有配置变更、DDL、数据迁移或回滚 SQL。保留已执行迁移及其校验值、数据库索引和已有审计数据。发布时应一起更新 Web/桌面前端和服务端。旧客户端请求审计列表会收到 404，已有第三方用量接口消费者若依赖已删除的统计字段也会受影响。回退时一起恢复前后端代码及对应接口契约即可。
