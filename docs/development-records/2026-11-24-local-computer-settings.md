# 本机电脑详情与 macOS 同卷存储迁移

2026-11-24。在本地 `master@4dfd317` 的任务分支 `codex/computer-settings-parity` 实现。

## 对照范围与界面入口

在已登录的 HiFox 客户端打开「本地机器详情」，通过滚动、截图和辅助功能树核对了从概览到机器信息的各节。OpenFox 原有设置页已经有多项控制，侧栏则只显示摘要。本次让两处复用同一份本机详情，沿用组织、中心地址、设备 ID 和所有者校验。远程电脑继续使用原有摘要和设置入口。

| HiFox 详情中的功能                                          | OpenFox 本次结果                                                                                                                       |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 电脑概览、Runtime、开发工具、绑定 Agent、机器权限和基本信息 | 侧栏本机详情复用已有设置页、操作和权限判断                                                                                             |
| CLI 版本、UUID、启动方式、后台服务及日志                    | 可查看启动时间、日志路径和脱敏日志，可启动、停止、重启服务，并可设置退出桌面端时是否默认保持服务运行                                   |
| 任务并发、持久会话、可用内存、负载保护                      | 本机所有者在线时可在详情内编辑。内存阈值支持 MiB 和 GiB，按整数 MiB 提交；会话和保护设置按守护进程返回的版本保存                       |
| 机器网络代理、缓存、清理策略                                | 在详情访问原有操作，可另外查看和更改本机数据目录                                                                                       |

| 组织工作流在本机执行、接电合盖保持唤醒                      | 组织工作流执行权限留作独立设计。本次电源功能覆盖打开桌面端时的空闲休眠；系统合盖策略仍由 macOS 管理                                    |

## 实施与迁移协议

1. 桌面原生接口在读取或修改本机设置前核验登录用户、组织、设备和完整中心地址。迁移目标来自系统文件夹选择器。用户确认后，再次核验身份及会话，传给 CLI 的路径来自主进程。
2. 在详情中停止本机服务后，选择同一 macOS 数据卷内的父目录。实际目的地始终为其下的 `OpenFox`。守护进程通过 launchd 状态、套接字以及身份、服务和运行锁确认可以移动。另一卷、与工作目录重叠、权限不安全或已有同名数据都会使操作失败。指向当前库的旧位置支持迁回。
3. 通过 macOS 的 `RENAME_SWAP` 原子交换原目录和预留链接。密钥、令牌、SQLite 数据库及其辅助文件、默认工作区均保留原 inode 和权限。稳定入口仍在 `~/Library/Application Support/OpenFox`，既有绝对路径及 Git 工作树引用可以继续使用。再次迁移时，将稳定入口直接指向新的物理目录。数据量不决定复制时间。
4. 迁移前持久化意图，同步相关目录，完成后清除待处理标记。下次访问可根据同卷 inode 判断交换发生在哪一侧，修复链接或释放预留目标。库缺失、目录身份不符或出现未知链接时返回错误，避免静默创建另一套设备身份。
5. 一次实际的工作区复验发现，工作区恢复还会比较规范化的绝对路径。SQLite 记录及共享任务清单统一保存稳定路径，在使用时仅转换已核验的存储根前缀。具体目录继续通过路径、Git 仓库和租约校验。外部用户仓库维持原位置。
6. 另行验证桌面端的服务并发控制。服务设置和代理同步曾竞争同一个忙碌标记，隔离 Electron 测试暴露了这一问题。两类操作现分别加锁；迁移期间，CLI 仍负责文件级排他控制。隔离进程退出时直接终止测试应用，避免测试用例停在交互式退出确认。

本次选择同卷目录交换。跨卷复制需要独立处理数据校验、外接盘断开及恢复；用户明确只需要同一 macOS 数据卷。SQLite 模式及中心端接口保持原样。桌面登录资料位于 Electron 自己的用户目录，守护进程日志位于 `~/Library/Logs/OpenFox`。用户另行配置在数据目录外的工作区仍由原路径管理。

## 配置与 SQL

| 文件或状态                                                     | 行为、默认值及影响                                                                                                                                 |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 桌面用户目录中的 `desktop-local-prefs.json`                    | 复用 `keep_service_running` 布尔值，默认开启，决定退出确认的默认选项。用户仍可在退出时调整                                                         |
| 桌面用户目录中的 `desktop-settings.json`                       | 沿用 `prevent_sleep` 控制任务运行期间的空闲休眠。限时防休眠仅保存在当前桌面进程                                                                    |
| `~/Library/Application Support/.openfox-storage-location.json` | 首次迁移时创建，权限 0600。记录数据目录 inode，迁移过程中附带源、目标和已有链接。旁边的 `.lock` 协调迁移及恢复。保留它和稳定入口，以便核对库的身份 |
| 数据目录内的 `storage-use.lock`                                | 使用该目录的新守护进程持有共享锁，迁移持有排他锁。锁在进程退出时释放                                                                               |
| 设备、服务、任务及代理配置                                     | 沿用现有配置文件和设置命令。设备身份、会话令牌和配置中的稳定路径随整目录迁移保留                                                                   |

产品代码没有新增依赖、环境变量、部署配置、SQL 语句、表结构、回填脚本或数据库回滚语句。SQLite 中已有读写语句的路径参数使用稳定路径；业务数据无需跑 SQL 迁移。文件系统交换只有在用户选定并确认目的地后才执行。

## 验证与回退

- macOS 上运行 `go test -race ./internal/daemon ./internal/daemon/workdir ./internal/daemon/supervisor ./cmd/openfox`。临时私有数据目录覆盖连续迁移、重复请求、迁回、同名冲突、跨卷拒绝、运行及身份锁、注册身份变更、交换前后恢复和替换目录拒绝。测试使用隔离 launchd 标签，未安装或停止真实用户服务。
- 使用真实 SQLite 文件验证迁移后的文件身份和行内容；用临时生成的设备密钥验证注册 ID、密钥及令牌。迁移前创建的真实 Git 共享任务迁移后可访问未提交文件、运行 Git 及重新取得工作区租约。迁移后创建的共享任务也能在迁回后重新打开。离线路径读取、会话绑定和工作区登记去重均有回归用例。
- `vitest run packages/app/src/computers/` 通过 7 个文件的 135 项测试，覆盖侧栏详情、保存内存设置、退出偏好、关闭日志弹窗、取消及完成位置更改。`pnpm --filter @openfox/desktop test` 通过 128 项测试。隔离 Electron 端到端用例通过真实主进程、preload 和本机 HTTP 身份校验，使用测试 CLI 和文件夹选择器替身核对实际迁移参数。
- 应用 TypeScript 类型检查及 `pnpm --filter @openfox/web build` 通过。CLI 的 Linux amd64 交叉编译通过，该平台继续返回不支持迁移。真实账号的数据目录、运行任务和设备身份未执行迁移。没有安装或发布桌面包，也没有测试硬件断电或合盖。
- 回退存储位置时，使用本版桌面端停止本机服务，选择原始父目录 `~/Library/Application Support`，确认后验证设备 ID 和任务目录，重新启动服务。如需换回旧版 CLI，应先迁回默认目录。若人工搬动或删除过目录，应先核对并恢复原数据与位置记录，保留现存链接。不要通过重新注册替代数据恢复。
