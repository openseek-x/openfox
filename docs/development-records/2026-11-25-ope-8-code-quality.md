# OPE-8 代码梳理与工程质量修复

基线为 `master@1f4d3db`。团队从 PR 即可检查本次提交的 Go、数据库、接口、Web、桌面和容器行为，master 发布引用同一质量工作流。具体目录和 24 项核查结论见[代码现状](../code-overview.md)。

## 来自真实数据库的修复

- 完整 Go 检查使用隔离 PostgreSQL，给内部 API、导出及渠道测试配置专用数据库。缺少数据库工具、测试进程失败、必需用例跳过或包无结果均能单独报告。仅外部模型、渠道浏览器等明确列举的夹具可以按条件跳过。
- 恢复演练最初发现中心纪元更新后，旧设备仍通过 HTTPS 领取新消息。派发选择、offer 列表、领取和准备后的启动许可现均检查设备已确认的纪元。原演练中，多出的一次 Runtime 调用消失。新消息排队，在途任务收到管理员取消后释放预留。
- 会话导出曾间歇返回 500。数据库记录了 `runtime_session_exports_expiry_valid` 约束失败，原因是创建时间和一小时后的到期时间分别取时。插入使用同一语句时间，回归断言两个时间正好相差一小时。
- 私聊事件按事务水位交付。集成测试先等写入事务进入可投递范围，再验证两名参与者能收到对应事件、其余两种身份看不到消息。注册身份测试使用同组织夹具，工作目录测试按当前接口传入存储路径。

## 契约、发布和前端

- OpenAPI 补充了密码登录、成员与设备、派发、核对、清理、通知及设备 WSS，另补 `/healthz`。按操作限制各 IM 服务商支持的注册方式。新增检查覆盖 645 个路径、774 项文档操作、776 条实际 API 路由及四个外层服务入口，校验生成类型和设备事件正反例。
- 中心以非 root 身份在容器中运行，应用与迁移使用同一版本的镜像。发布流水线附带 Linux amd64 镜像归档及摘要。Compose 命令、显式迁移和本机使用说明见[部署文档](../../deploy/README.md)。
- 清理无调用方的内存调度实现，统一多渠道 Runtime 配置名，移除配置包对 Office 业务包的依赖。生产容量预留、领取及过期回收继续走 PostgreSQL。
- React Hooks 检查覆盖工作区。任务创建和表情选择复用本地存储容错，产物切页、表格绘制及搜索历史按实际数据变化更新。浏览器验收覆盖本机存储受限的建单、按真实拖放区域移动任务、窄屏切换以及生产 Office 页面。
- 迁移首页逐项链接 175 个实际 SQL，并有顺序回归。稳定规则、集成文档、平台支持范围和已有开发记录均可从仓库内找到。

备份恢复后，管理员仍需处置恢复前的在途 Run。本机验证的边界包括临时 PostgreSQL、模拟 Runtime 及 Chromium。依赖外部模型账号、渠道服务、真实桌面签名和 GitHub 生产投递的部分需在其对应环境验收。
